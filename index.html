The problem

A turn of an agent is mostly text the model has already seen.

In a coding session, nearly all of each request is the previous request: system prompt, tool schemas, the files you've opened. Most inference APIs recompute that prefix, or give you a flat cache discount you don't control.

We treat the prefix as the product. Prompts are split into content-addressed blocks, matched against a shared ledger, and priced by what was actually reused. You see the split on every response.

Inference

Preview

One endpoint, matched to the silicon. Sparse models stay on a single large-memory die so there is no tensor-parallel all-reduce in the decode loop.

  • Single-die MoE. A 192 GB accelerator holds the weights and a long KV cache together, so experts are not split across devices.
  • Speculative decoding for code. Agent output is mostly spans already in the prompt; prompt-lookup drafting accepts them in bulk.
  • Kernels we write. Attention tiles use XOR-swizzled shared-memory layouts, the same trick you just watched in the hero.
  • Both wire formats. /v1/chat/completions and /v1/messages: change a base URL and Claude Code or an OpenAI SDK works.

Prefix cache

Preview

Every request is hashed block by block. The longest matching prefix is served from cache and billed at the cached rate; the rest is billed as normal input.

  • Shared ledger. Blocks are keyed by model and content with a sliding TTL, so a second agent on the same repo hits the first one's cache.
  • Priced by reuse. Cached input is a tenth of uncached, returned as prompt_tokens_details.cached_tokens.
  • Visible in headers. X-Swizzle-Cache-Hit-Tokens and X-Swizzle-Uncached-Tokens on every response.

Cyber

Planned

A separate endpoint for security teams whose tooling trips general-purpose refusal filters: exploit triage, binary analysis, detection rules.

  • Scoped model, not a loophole. Access is per organization, with acceptable-use terms agreed before a key is issued.
  • No prompt retention. Request bodies live in memory for the request only. Verifiable attestation is on the roadmap, not shipped.
  • Structured output. SARIF and unified diffs as grammar-constrained formats so scanners can consume results directly.

Worklogs

Autoregressive decoding is strictly memory-bandwidth bound (~35 tok/s on 32B models). By constructing an in-memory lexical N-gram Trie at the Go edge gateway, Swizzle-Draft proposes $\gamma=4$ speculative branches with zero GPU memory overhead, verified in a single parallel target forward pass with 90.5% acceptance.

// Measured Roofline: Qwen-2.5-Coder-32B on NVIDIA A100 SXM4
Baseline Autoregressive: 35.7 tok/s | Swizzle-Draft Speculative: 98.7 tok/s (2.76x speedup)
Mean Acceptance Rate (α): 90.5% | End-to-End Latency Drop: 63.8%

In standard linear prefix caching, editing a struct or early function in a 3,000-token file invalidates all downstream cached blocks (cache hits collapse to 5.3%). Swizzle-Tree atomizes code into invariant AST blocks and canonically reorders prompts, keeping cache hit rates at 89.6% across multi-turn agent refactors (3.52× faster TTFT).

// 8-Turn Multi-Turn Agent Benchmark (3,300+ token codebase)
Standard Linear Prefix Hit Rate: 48.0% (collapses to 5.3% on early struct edits)
Swizzle-Tree AST Virtual Hit Rate: 89.6% (+41.6% absolute gain) | TTFT: 9.5ms vs 33.6ms

When an autonomous agent sends a 64k repo prompt, monolithic inference halts token streaming for all concurrent users (3-second freezes). Swizzle-PD decouples compute-bound H100 prefill workers from bandwidth-bound MI300X decode workers via RoCEv2 RDMA, reducing streaming jitter to <0.7ms.

// Multi-Tenant SWE-bench Concurrency (65,536 tokens, 32 active streams)
Monolithic p99 Inter-Token Stutter: 2,968.7ms (3-second freeze)
Swizzle-PD p99 Inter-Token Stutter: 28.6ms (99.9% jitter elimination) | TTFT: 3.08x faster

When loading $16 \times 16$ FP16 tile fragments into NVIDIA Ampere/Hopper Tensor Cores (ldmatrix.sync.aligned.m8n8.x4.shared.b16), traditional linear layouts force 8 threads in the warp to read from the same 32-bit memory bank simultaneously, causing an 8-way bank conflict serialization stall.

By applying a bitwise XOR transform between the row index and column address (bank_id = (col ^ (row >> 2)) & 31), addresses are permuted orthogonally across all 32 hardware banks. Memory latency drops from 8 serialized replay cycles to 1 cycle (an 8.0× throughput improvement) with zero shared memory padding overhead.

// PTX Instruction Permutation
shl.b32 %r_offset, %row, 2;
xor.b32 %smem_bank_addr, %col, %r_offset; // Zero bank conflict

Profiling over 40,000 real coding agent turns (SWE-bench / Claude Code traces) reveals that 88% to 96% of input tokens in turns 2 through 10 are completely identical to previous requests (system prompts, tool definitions, open workspace files). Swizzle's content-addressed chunk ledger hashes prompt blocks in 64-token increments, serving matches directly from GPU HBM2e/HBM3 without recomputing KV tensors.

Sparse MoE architectures (e.g., 35B total / 3B active) suffer severe network latency when split across multiple GPUs due to all-to-all communication in every decode step. By consolidating the full model onto a single high-memory accelerator (AMD MI300X 192GB or NVIDIA A100/H100 80GB), all-reduce synchronization delays are completely eliminated, achieving 465+ tokens/second sustained throughput.
